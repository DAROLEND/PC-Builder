# Як я використовував AI

Код цього проєкту здебільшого написав Claude Code за моєю специфікацією і під моїм наглядом. Тут чесно описано, що саме я делегував, де AI помилявся і як це знайшли (розділ 2 — фактичний журнал розробки, нічого не вигадано), що я перевірив сам і чого не перевіряв ніхто.

## 1. Що делеговано

Проєкт згенеровано за допомогою **Claude Code** за моєю специфікацією: предметна область, стек, вимоги до валідації, permissions, агрегацій, фонових задач, інтеграцій, інфраструктури та AI-порадника.

Claude Code написав:
- модель даних і рушій сумісності з 13 групами правил;
- DRF API, permissions, фільтри, агрегації, OpenAPI-схему;
- Celery-задачі, інтеграції з НБУ, Stripe, Claude API;
- фронтенд на React + TypeScript + TanStack Query;
- тести, Docker Compose, CI, Render Blueprint, цей README.

Як перевірялося під час генерації (не «на око»):
- 160 backend-тестів (зараз 286) на **справжньому PostgreSQL 17**, а не на SQLite, бо JSONB, GIN, віконні функції та `select_for_update` на SQLite поводяться інакше або відсутні;
- `ruff`, `makemigrations --check`, генерація OpenAPI з `--fail-on-warn`;
- `tsc`, `oxlint`, Vitest, production-збірка фронтенду;
- запуск живих серверів і наскрізний сценарій через HTTP: реєстрація → збірка → замовлення → оплата → порадник;
- прохід у справжньому браузері (Playwright + Edge) зі скриншотами й перевіркою консолі на помилки;
- реальний виклик API НБУ.

## 2. Де Claude помилився і як це знайшли

Нижче всі помилки, знайдені під час генерації. Колонка «Як знайшли» важлива: більшість з них не впала б сама по собі, їх виловив конкретний механізм перевірки.

## 3. Що я перевірив сам

- **Дані каталогу.** Вибірково звірив ціни й характеристики деталей демо-каталогу (сокети, чипсети, розміри) з джерелами, розбіжностей не знайшов.
- **Живий сайт.** Пройшов основні сценарії на задеплоєній версії, зокрема спроби відкрити чи змінити чужі дані (приватну збірку, коментар, замовлення). Доступ закритий, як і задумано.
- **Пороги рушія сумісності** (`backend/apps/builds/compatibility.py`), і чому вони саме такі:
  - **Запас БЖ 30 %** (`PSU_HEADROOM = 1.3`). Оцінка споживання — це сума TDP, а сучасні відеокарти дають короткі сплески вище за свій TDP. Із запасом блок під навантаженням працює на ~75 % потужності: там вищий ККД, менше нагрівання й шуму, і сплески не вимикають захист.
  - **«Тісно» — менше 10 мм** (`GPU_TIGHT_FIT_MM = 10`). Довжина з характеристик корпусу рахується до голої стінки, а кабелі живлення, передні вентилятори чи радіатор забирають частину місця. Тому це попередження, а не помилка: карта влізе, але монтаж може бути незручним.
  - **Кулер порівнюється з потужністю під навантаженням, а не з TDP** (моя знахідка, пункт 22): Intel `max_power_w`, для AMD — PPT = 1,35 × TDP.
- **Фільтр «лише сумісні» (`backend/apps/catalog/compat_query.py`)** — це попередній фільтр, а не заміна рушію. Прості жорсткі правила (сокет, тип пам'яті, габарити) перекладено в SQL, щоб пагінація й сортування лишались у базі. Складні правила й попередження перевіряє тільки рушій. Контракт: фільтр може пропустити деталь, на яку рушій потім попередить, але ніколи не ховає валідну деталь. Пункт 23 — випадок, коли цей контракт порушувався.

## 4. Чого AI не зробив або не зміг перевірити

- **Docker Compose локально не запускався**, бо на машині розробки немає Docker. Його перевіряє GitHub Actions: збирає образи, піднімає весь стек із 7 сервісів і робить smoke-тест. Перший прогін CI після пушу був зеленим з першої спроби. Продакшн-оверлей (`docker-compose.prod.yml` з Caddy і HTTPS) в CI не запускається, бо для сертифіката потрібен справжній домен.
- **Шлях із Claude API** протестовано скриптованим фейковим клієнтом (форма запиту, відхилення невалідної збірки, fallback при відмові). Реального виклику з ключем не було, і живе демо зараз працює без ключа, на детермінованому планувальнику.
- **Stripe** протестовано моками (підпис вебхука, обробка події). Реальної тестової оплати не було; живе демо використовує фейковий провайдер.
- **Деплой** на VPS не виконувався: інструкцію й конфіги підготовлено (`docs/DEPLOY.md`). Демо розгорнуто на безкоштовному хостингу Render + Neon: <https://pcbuilder-ife5.onrender.com>.
- **Умови використання hotline прочитано лише наприкінці, і це помилка AI.** Увесь збір даних будувався на тому, що robots.txt дозволяє сторінки товарів і не забороняє `/svc/`. Але [угода користувача](https://hotline.ua/ua/page/user_agreement/) прямо забороняє парсинг без письмового дозволу (п. 6.4) і копіювання матеріалів без письмової згоди (п. 2.4). robots.txt — технічна підказка для ботів, а не дозвіл, і AI мав перевірити угоду до першого запиту, а не після. Висновок: збір даних за замовчуванням вимкнено перемикачем `MARKET_FETCH_ENABLED=0`, адміністрації hotline надіслано запит на дозвіл, відповіді поки немає. На живому демо (некомерційний навчальний проєкт) збір увімкнено. Внутрішній GraphQL для історії цін (`/svc/frontend-api/graphql`) AI знайшов у JS-бандлі й підключив за згодою власника проєкту, так само не звіривши це з угодою.
- **Посилання на hotline** для 65 деталей знайдено через веб-пошук, 8 недоступних моделей замінено найближчими аналогами. Усі посилання перевірено парсером (назва на сторінці збігається), але специфікації замінених моделей (довжина відеокарт тощо) варто звірити з сайтами виробників.
